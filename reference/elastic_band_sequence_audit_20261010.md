# Elastic Band 연속 상태 재생 점검 (2026-10-10)

IPC 정지선 rosbag의 입력·원본 내부 경로·최종 출력을 동일한 헤더 시각으로 짝지어 470프레임 연속 재생했다. 첫 직전 내부 경로만 원본으로 초기화하고 이후에는 독립 계산의 이전 상태를 사용했다.

```bash
python3 tests/elastic_band_sequence_rosbag_replay.py \
  /tmp/planning-aa-prox-build/elastic_band_sequence_runner \
  /home/sujin/Documents/01_GIT/01_OSS/251231_KCity/ipc/rosbag_stopline/rosbag_20251231_132036_0.db3 \
  --start 30 --frames 470 --allow-count-differences
```

원본 `resamplePoseVector`처럼 Akima 재표본화 뒤 점의 방향을 다시 계산하고, 첫 번째 재표본화 점을 원래 이전 경로의 첫 자세로 복원했다. 입력 정지점은 원본과 같이 최적화 경로에 먼저 삽입한 다음 입력 뒤쪽 경로를 연결한다. 연결부 정지점 삽입은 연결 구간에만 적용한다. 입력 경로의 종점 영속도는 원본의 투영·거리 조건을 통과할 때만 최종 경로로 옮긴다.

이 변경 전에는 점 수가 다른 프레임이 81개, 내부 최대 위치 차이가 0.923459m, 최종 최대 위치 차이가 0.139622m였다. 변경 뒤 **재계획 470회, 상태 초기화 0회, 점 수 차이 0프레임**, 내부 최대 위치 차이 0.000057m(93번), 최종 최대 위치 차이 0.001708m(229번)이다. 속도는 76프레임에서 각 1점씩 다르고 최대 차이는 11.111111m/s다. 첫 차이는 336번 프레임의 마지막 점이다. 두 계산의 종점 좌표가 매우 가까워 원본의 정지점 투영 경계가 양쪽에서 달리 판정되는 사례이며, 아직 원본과 속도 동등성이 성립하지 않는다. 예를 들어 336·338번은 독립 출력만 종점 영속도이고 341번은 원본 출력만 영속도다. 원본 입력의 마지막 점은 334~341번 모두 영속도인데 원본 출력의 마지막 점은 334·336·338번에 11.111m/s, 335·337·339~341번에 영속도다. 그러므로 입력 종점의 영속도를 출력에 무조건 복사하는 보정은 원본의 이 경계 동작을 재현하지 못한다. 원본 이전 내부 경로를 주입한 334~336번 단일 프레임은 각각 일치하므로 장기 연속 상태의 작은 수치 차이가 관여한다.

동일한 독립 평활화 결과를 경로 최적화에 직접 넘긴 첫 100프레임 재생에서는 비교 대상 70프레임의 평활화 점 수가 모두 같고 최대 위치 차이는 0.001550m, 속도 차이는 0이다. 최적화는 100프레임 모두 계산했으나 89번 한 프레임의 점 수가 다르고 최대 공통 점 위치 차이는 1.000470m다. 이 차이의 차량 상태 수신 시각 영향을 아래에서 분리했다.

89번 프레임의 행동 경로 수신 시각은 `1767154847644731383ns`, 평활화 경로 수신 시각은 `1767154847649285703ns`로 4.554ms 차이가 났다. 그 사이 새 odometry가 `1767154847647373399ns`에 기록돼 자차 XY가 약 0.061m 이동했다. 원본 `PathOptimizer::onPath`는 평활화 경로 콜백에서 최신 odometry를 읽는다. 재생기에서 Elastic Band에는 행동 경로 수신 시각의 odometry를 유지하고, 최적화에만 그 콜백 수신 시각의 odometry를 선택하면 ProxSuite 기준 비교 대상 70프레임의 **최적화 점 수 차이 0, 속도 차이 0**, 최대 공통 점 위치 차이 **0.039122m(61번)**로 바뀐다. 기록된 평활화 경로를 최적화 입력으로 대체하거나 평활화 출력의 마지막 `is_final` 값을 대신 쓰는 진단은 ProxSuite와 ADMM 모두에서 89번 차이를 없애지 못했다. 따라서 89번의 점 수·속도 차이는 이 재생기에서 차량 상태를 앞 단계의 수신 시각으로 고르던 선택과 연결된다. 실제 ROS executor의 콜백 처리 순서까지 복원한 것은 아니며 다른 위치 잔차가 남는다.

이 두 단계의 차량 상태 시각을 분리한 채 IPC 정지선 **전체 571프레임**을 ProxSuite로 재생하면 두 계산 모두 571회 성공한다. 처음 세 프레임은 기록에 대응하는 평활화 수신 시각이 없어 행동 경로 수신 시각을 쓰지만 비교에서 제외한다. 앞 30프레임을 제외한 541프레임에서 평활화 점 수 차이 **0**, 최대 위치 차이 **0.001708m**이며, 최적화 점 수 차이 **0**, 속도 차이 **0**, 공통 점 최대 위치 차이 **0.039122m(61번)**다. 평활화 종점 속도 차이는 여전히 존재하고 최대 11.111111m/s다. 기존의 최적화 점 수 차이 4프레임(89·100·134·166번)은 한 단계의 차량 상태를 두 단계에 공통 적용한 재생 조건에서 나온다. 독립 최적화의 모든 점이 원본과 일치했다는 뜻은 아니며, 다른 기록의 상태 정렬과 0.039m 위치 잔차는 남는다.

이 두 단계 재생기는 첫 프레임을 빈 내부 상태에서 시작한다. HPC S자·IPC 끼어들기의 처음 100프레임을 같은 방식으로 단순 실행하면 평활화부터 각각 55·70프레임의 점 수 차이가 발생했다. 앞서 원본 직전 내부 경로로 초기화한 별도 Elastic Band 연속 시험의 결과를 이 빈 상태 실행과 섞어 판단하지 않는다. 두 기록을 종단 최적화까지 대조하려면 첫 직전 내부 경로와 최적화 이전 상태의 초기화를 먼저 맞춰야 한다.

```bash
python3 tests/eb_optimizer_chain_rosbag_replay.py \
  /tmp/planning-aa-prox-build/eb_optimizer_chain_runner \
  /home/sujin/Documents/01_GIT/01_OSS/251231_KCity/ipc/rosbag_stopline/rosbag_20251231_132036_0.db3 \
  --frames 100 --assert-ipc-stopline-chain

ctest --test-dir /tmp/planning-aa-prox-build --output-on-failure \
  -R '^eb_optimizer_ipc_stopline_state_at_smooth(_full)?_replay$'
```

이 두 단계 재생은 행동 경로 입력과 odometry의 기록 시각을 사용한다. 실제 원본 콜백이 소비한 시각과 원본 QP 풀이기의 미세 수치 상태까지 동일하다고 증명하지 않는다.

같은 독립 연속 재생기를 HPC S자(`hpc/rosbag_scurve/rosbag_20251231_022311_0.db3`)와 IPC 끼어들기(`ipc/rosbag_cutinout/rosbag_20251231_133116_0.db3`) 기록에 각각 `--start 30 --frames 500`으로 실행했다. 두 기록 모두 재계획 500회·초기화 0회·최종 점 수 차이 0프레임·속도 차이 0프레임이다. S자의 내부/최종 최대 위치 차이는 0.008168/0.008219m, 끼어들기는 0.000036/0.000045m다. 따라서 IPC 정지선의 종점 속도 잔차를 다른 두 기록에 일반화하지 않는다.
