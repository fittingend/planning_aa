# 장애물 순항 콜백 경계와 설정 대조 (2026-10-10)

기준 decision launch `obigo_launch/sample_adsw_decision_run.launch.xml`이 참조하는 `obigo_launch/config/planning/scenario_planning/lane_driving/motion_planning/obstacle_cruise_planner/obstacle_cruise_planner.param.yaml`의 정지 설정은 외부 객체 횡방향 시간 4.5초, 횡단 객체 충돌 여유 1.0초, 이전 정지 객체 유지 시 속도 상한 1.5m/s다. 패키지 자체의 `planning/autoware_obstacle_cruise_planner/config/obstacle_cruise_planner.param.yaml`에는 각각 4.0초, 4.0초, 3.5m/s가 적혀 있다. 독립 코어 기본값은 **기준 launch**를 따른다. 패키지 기본 YAML의 숫자를 기준 실행값으로 적용하면 안 된다. K-City 기록의 실제 런타임 파라미터 덤프는 없으므로 이 정적 설정과 기록 실행값이 같았다고 단정하지 않는다.

HPC S자 기록의 앞 650개 유효 입력을 `tests/obstacle_cruise_projection_rosbag_replay.py`와 객체 후보 실행기에 순서대로 넣었다. 원본 `stop_planning_info` 정지 활성 434프레임 중 독립 정지 활성은 376프레임이며, 원본만 활성인 58프레임이 남는다. 원본 감속 활성 42프레임은 독립 감속에도 모두 포함되지만 독립만 활성인 49프레임(482–530번)이 남는다. 두 계산이 동시에 활성인 42프레임에서 원본 활성 구간에만 상태를 갱신한 안정화 속도의 최대 차이는 0.000190m/s다. 376개 동시 정지 활성의 정지 여유 거리는 전부 기준 6.0m와 일치한다. 감속만 활성인 여분 프레임은 원본 정지만 활성인 구간과 겹친다.

477번 궤적 수신 시각에는 직전 예측 객체 메시지가 차량 ID `2b2cc950`을 담았고, 원본 정지 marker가 가리키는 차량 ID `ad879cf7`의 메시지는 궤적보다 약 2.95ms 뒤에 기록됐다. marker는 약 4.69ms 뒤에 기록됐으며 위치도 뒤의 객체 메시지와 맞는다. 따라서 궤적 수신 시각의 직전 객체 메시지를 무조건 선택하는 오프라인 재생은 원본의 실제 콜백 입력을 복원하지 못한다. 객체 조회 시각을 5ms 뒤로 옮기면 독립 정지 활성은 384프레임으로 늘지만 원본만 활성 50프레임과 독립만 활성 감속 54프레임이 남는다. 15ms 뒤로 옮기면 다른 객체 묶음을 선택해 원본 감속 활성 42프레임 중 31프레임을 놓친다. 고정 시간 이동으로 해결할 수 없는 콜백 경계다.

정지 후보 실행기는 실제 예측 객체와 점별 경로를 사용하고, 최종 정지점·감속 삽입의 활성 차이를 추적한다. 원본 내부 콜백 순서와 사용한 객체 메시지 식별자는 rosbag만으로 확정하지 못했다. HPC S자 bag에는 `/parameter_events` 토픽이 선언돼 있으나 메시지는 0개였고, `/rosout` 9,076건에서 장애물 순항 관련 일치는 recorder의 구독 로그와 외부 속도 제한 요청뿐이었다. [로그 감사 코드](planning_rosout_audit.py)에서도 노드 파라미터 덤프를 찾지 못했다. 이 수치를 코어의 원본 완전 동등성으로 해석하지 않는다. 다음에는 기록 당시 원본의 실행 파일·파라미터 덤프와 입력 객체 헤더 시각/ID, 경로·차량 상태 시각, 출력 marker를 동일 콜백 단위로 함께 수집해야 한다.

정지 표식 `obstacles_to_stop`의 위치를 이용해 각 궤적 시각의 전후 객체 메시지 중 가장 가까운 자세를 **출력 정보로 역선택**해 보았다. 앞 650프레임 중 417프레임에서 표식과 객체 자세가 0.1m 이내였고, 그중 147프레임의 선택된 객체 메시지는 궤적 수신보다 나중에 기록됐다. 그러나 이 역선택 입력으로 재계산한 정지 활성은 375프레임으로 기존 직전 메시지 방식의 376프레임보다 오히려 1개 줄었다. 원본 정지 434프레임과의 차이는 59개다. 감속 원본 42프레임 중 독립 활성도 41개가 됐다. 표식 위치만으로 전체 예측 경로·콜백 짝을 확정할 수 없다는 진단이다. 재현 옵션은 `--marker-guided-object-pairing`이며 운영 입력 선택에 쓰지 않는다.

원본만 정지한 구간의 첫 사례인 **유효 입력 478번**(초기 입력 준비 전 궤적 19개 제외)에서 독립 계산은 현재 객체 외형 충돌을 찾았지만, 약 8.73초 뒤의 미래 외형이 경로 다각형에서 약 1.42m 떨어져 `TransientInsideObject`로 제외했다. 원본 정지 디버그는 같은 시점에 약 20.50m 앞의 정지를 기록했다. `--stop-vehicle-shape sample`로 재생하면 정지 누락 58프레임 중 **49프레임**은 이 독립 미래 통과 판정을 포함한다. [원본 이미지 재실행](obstacle_cruise_live_replay_20261010.md)에서도 패키지 쪽 객체 속도·충돌 시간 설정을 적용한 현재 노드는 450–482번 연속 입력의 478번부터 객체를 `intentionally_ignored_obstacles`로 분류한다. 기록 당시 노드는 계속 정지했다. 기록 실행 파일·파라미터·실제 polling 입력의 차이가 남아 있으므로 이 분기의 점별 동등성은 미확인이다.

현재 이미지 노드를 450–649번까지 연속 재실행한 후 기록과 비교하면 원본만 정지한 58프레임(478–535번) 모두 현재 이미지에서도 정지하지 않았다. 독립 계산과 현재 이미지가 이 58프레임의 **정지 활성 여부**에서 같은 방향이라는 점은 확인됐지만, 감속은 현재 이미지 단독 36프레임(482–517번)과 기록 단독 42프레임(531–572번)으로 나뉘었다. 이 차이는 기록 당시 실행 조건의 미확인을 더 좁혀 주지만, 독립 감속 계산의 수치 동등성을 증명하지 않는다.
